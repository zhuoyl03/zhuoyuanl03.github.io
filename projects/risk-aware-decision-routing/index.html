Risk-Aware Decision Routing under Limited Review Capacity

Zhuoyuan Li · Research project, 2026

Code Experiment report Method

Which cases should receive review?

When only some predictions can be reviewed, uncertainty and the consequences of an error are different priorities. I study this distinction on disaster-image informativeness classification, using damage-severity annotations to assign different costs to mistakes.

I built a batch-routing pipeline around a fixed ViT backbone and three prediction heads. A small mixture model estimates a loss distribution for each model action. The router chooses a model and allocates the review budget using either expected cost or conditional tail risk (CVaR), compared with an entropy-based baseline. True severity labels are never available to the router at inference.

A tradeoff at the same review budget

Each policy sends 3,126 of 15,634 images for review, approximately 20%. Values below are means over router seeds 17, 42, and 73. Lower is better for both outcomes.

Tail-risk routing leaves about 34% fewer severe errors than entropy routing, but increases aggregate weighted error cost by about 35%. It changes which mistakes remain; it does not improve both objectives.

When to keep the baseline

I separated router fitting, policy selection, and an adoption check within the development data. The selection stage chose mean-risk weighting in all three runs. On a separate guard subset, paired bootstrap comparisons did not support switching from entropy in any run, so the implemented fallback retains it. A review budget outside the checked 20% setting also falls back to entropy.

The evaluation includes simpler routing baselines, exact-image deduplication, and paired blur and JPEG checks on 3,000 images. The code includes tests for risk calculations, review-budget allocation, and fallback behavior.

Evaluation scope

This is an exploratory offline study. Review is simulated as perfect in the main results, and severity costs of 1, 3, and 8 are illustrative rather than measured real-world harms. All prediction heads run before routing, so these experiments do not demonstrate inference-cost savings.

The backbone was selected using the original development split, and historical test results had already been inspected. The adoption check was added after an initial experiment; it is not a blind final evaluation or a safety guarantee. A stronger test would use fresh event-held-out data and observed reviewer outcomes.
